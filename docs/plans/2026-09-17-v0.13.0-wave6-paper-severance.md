# v0.13.0 Wave 6 — Paper-Plane Structural Severance (P1: DB Core)

> **For implementers:** This is **P1 of 7** (P1 DB core → P2 pgTAP guard → P3 digital two-phase → P4 RBAC/participation → P5 dashboard prune + verify redesign → P6 hygiene → P7 `members.csv` history purge). P1 is the critical path; P2–P7 depend on it. This project has **no unit-test suite** — DB verification is a rolled-back `DO $$ … RAISE EXCEPTION` harness applied through the **Supabase MCP** (orchestrator-owned), `@verifier` for build/lint, Playwright for UI UAT. Migrations are applied via the Supabase MCP (`apply_migration`); the `.sql` file is source-of-truth + run order. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Structurally sever the paper identity plane from the anonymous ballot plane so no durable row, audit row, RPC argument set, or RPC return set co-locates `member_id`/`short_code` with `ballots.ballot_id`/`candidate_id`. Clears the council's real-PII **NO-GO** (C1 `vote_audit_log` register, C2 shared `ballot_id` join). C3 (service-role/superuser insert-order/timing correlation) is an **accepted deferred residual**.

**Architecture:** One new terminal-writer migration, `supabase/migration_wave6_paper_severance.sql` (canonical run-order **item 34**, immediately after Wave 5 items 30–33). It: (1) adds immutable `election_settings.paper_ballot_layout`; (2) adds token reservation columns; (3) creates the member-blind `anonymous_paper_blanks` pool; (4) creates split audit tables (`participation_audit` identity-only, `ballot_audit_log` ballot-only), each with a `CHECK` rejecting the opposite plane's handles; (5) drops old matched-pair paper RPCs; (6) repurposes `paper_ballots` as an identity-only table (no `ballot_id`/`candidate_id`), migrating legacy history; (7) retro-scrubs `vote_audit_log` + installs no-colocation `CHECK` + trigger + append-only trigger; (8–19) new split RPCs (`check_in_paper_voter`, `generate_anonymous_blank_ballot_pool`, `submit_paper_vote` returning `receipt_code` only, `correct_paper_vote`, `spoil_paper_check_in`, `void_anonymous_paper_blank`, reconciliation) + fail-closed deprecated shims + public service-role wrappers; (20) grants/revokes.

**Tech Stack:** Supabase Postgres — `SECURITY DEFINER` RPCs in `private` schema, `SET search_path = public, private, extensions`, RLS + explicit `service_role` grants (per the 42501 gotcha).

**Branch:** `agent/v0.13.0-wave6-paper-severance` (per AGENTS.md — never main/master).

**Design source:** `docs/specs/2026-09-17-v0.13.0-anonymity-design.md` §5A/§5B/§5C, Decision C (locked, user sign-off 2026-09-17; committed `6adb161`).

- [ ] **Step 3 — Split-audit CHECK constraints reject the opposite plane (test against KNOWN-BAD input, per AGENTS.md guard rule).** Run in a rolled-back block; each INSERT must RAISE:
```sql
DO $$
BEGIN
  -- participation_audit must reject a vote handle in details
  BEGIN
    INSERT INTO participation_audit(action,member_id,channel,details)
    VALUES ('X',(SELECT id FROM members LIMIT 1),'PAPER','{"ballot_id":"x"}'::jsonb);
    RAISE EXCEPTION 'FAIL: participation_audit accepted ballot_id';
  EXCEPTION WHEN check_violation THEN NULL; END;
  -- ballot_audit_log must reject an identity handle in details
  BEGIN
    INSERT INTO ballot_audit_log(action,channel,details)
    VALUES ('X','PAPER','{"member_id":"x"}'::jsonb);
    RAISE EXCEPTION 'FAIL: ballot_audit_log accepted member_id';
  EXCEPTION WHEN check_violation THEN NULL; END;
  RAISE EXCEPTION 'ROLLBACK_OK: both guards fired correctly';
END $$;
-- EXPECT: final RAISE 'ROLLBACK_OK…' (proves guards reject bad input, then rolls back)
```
- [ ] **Step 4 — `vote_audit_log` no-colocation guard fires on known-bad input.**

## Risks / accepted residuals (from D-step reconciliation)

- **C3 (accepted, deferred):** a service-role/DB-superuser adversary can still correlate `participation_audit.created_at` (check-in) with `ballots.created_at` (record) by insert-order/timing. Structural severance does not defeat this; documented residual per spec §3 re-scope.
- **N1:** the single VOTING token is *consumed* (`is_used=TRUE`) at check-in with a release path via `spoil_paper_check_in`. This preserves single-token FOR UPDATE mutual exclusion (Decision D) but the new `reserved_at`/`reservation_released_at` columns are partly redundant with `is_used`. Not a blocker; note for P3 when digital reuses the same token.
- **N2:** `paper_ballots.status='VOTED'` is now unreachable on the identity plane (recording moved to `anonymous_paper_blanks`) — vestigial enum value, harmless.
- **N3:** the SEC-18 hash-chain rebuild is guarded by `to_regprocedure(...)`; if the `compute_audit_log_hash` signature has drifted it silently skips — Task 2 Step 8 exists to catch that.
- **Check-in-without-record gap:** if a voter checks in (token consumed) but never records and is never spoiled, the entitlement stays burned. Tally is a blind `ballots`-only count (never member-inferred), so this is a reconciliation gap, not an anonymity leak. Surfaced via `paper_pool_reconciliation()`.
