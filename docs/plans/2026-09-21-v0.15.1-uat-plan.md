# UAT Plan — v0.15.1 (Wave 10 post-launch + eligibility phase-gate)

**Date:** 2026-09-21
**Tag under test:** `v0.15.1` (`ce28648`)
**Environment:** Local dev — `http://localhost:3000` (Playwright `webServer` starts `npm run dev`)
**Browser:** Chromium, **headed** (user follows along on screen)
**DB:** Shared Supabase, **TEST DATA** (302 members, 4 candidates, phase = `VOTING`)
**Spec:** `tests/uat-v0151.spec.ts`
**Legacy spec:** `tests/uat.spec.ts` is NOT run as-is — several cases assume `SETUP`/`COMPLETED` phase or mock `/api/admin/phase` and will false-fail against live `VOTING`. Covered selectively below where still valid.

## Legend

| Tag | Meaning |
|-----|---------|
| `[AUTO]` | Playwright performs the step; no human input |
| `[USER]` | **Requires the human** — enter secret, click email link, cast a real vote, camera/QR, etc. Test pauses and prints a banner |
| `[WATCH]` | Automated, but the user should visually confirm the headed browser |
| `[API]` | Direct HTTP assertion (via `page.request` with session cookies) — no UI interaction |
| `[NEG]` | Negative / guard test — must fail closed |
| `[MUT]` | Mutates test data (check-in, record, spoil, dispatch) — acceptable on TEST DATA |
